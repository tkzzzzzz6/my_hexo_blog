# Codex 常用快捷键与使用技巧速查

> 适用于 Codex CLI 交互式终端。不同版本、终端和操作系统的键位可能略有差异。
> 本文中的 `Ctrl+...` 表示同时按下组合键，`/命令` 表示在 Codex 输入框中输入的斜杠命令。
> Codex 的具体模型、权限和可用命令以当前安装版本显示的 `/help` 为准。

## 一、Codex 的基本工作方式

Codex 通常围绕三个对象工作：当前工作目录、对话上下文和工具权限。

```bash
codex                       # 在当前目录启动 Codex
codex "检查并解释这个项目的启动流程"  # 以初始任务启动
codex --help                # 查看命令行参数
codex --version             # 查看当前版本
codex resume                # 恢复历史会话
```

进入交互界面后，Codex 会根据任务读取文件、执行命令、修改代码，并在需要时请求确认。建议先确认当前目录和 Git 状态，再开始让 Codex 修改文件。

## 快速速查表（Cheat Sheet）

| 操作场景 | 核心命令 | 说明 |
| :--- | :--- | :--- |
| **启动 Codex** | `codex` / `codex "任务描述"` | 在当前目录启动会话 / 带初始任务启动 |
| **查看帮助** | `codex --help` / `/help` | 查看 CLI 参数 / 查看会话内命令 |
| **查看版本** | `codex --version` | 查看当前安装的 Codex 版本 |
| **恢复会话** | `codex resume` | 选择并恢复历史会话 |
| **查看状态** | `/status` | 查看工作目录、模型、权限和上下文状态 |
| **切换模型** | `/model` | 查看或切换当前会话使用的模型 |
| **查看权限** | `/approvals` / `/permissions` | 查看或调整审批和权限设置 |
| **提交请求** | `Enter` | 提交当前输入框中的任务 |
| **中断任务** | `Ctrl+C` | 停止生成中的回复或正在执行的命令 |
| **压缩上下文** | `/compact` | 对较长对话进行压缩，保留核心信息 |
| **清理会话** | `/clear` | 清理当前对话内容或开始新的上下文 |
| **查看差异** | `git diff` / `/diff` | 查看代码修改（`/diff` 取决于版本） |
| **代码审查** | `/review` | 审查当前修改（取决于客户端和版本） |
| **退出会话** | `Ctrl+D` / `/exit` | 退出当前 Codex 会话 |

> 斜杠命令可能随 Codex 版本和客户端形态变化。命令不可用时，优先执行 `/help` 查看当前环境支持的命令。

## 二、输入框核心快捷键

```text
Enter                     # 提交当前请求
Ctrl+C                    # 中断正在生成的回复或运行中的命令
Ctrl+D                    # 退出当前 Codex 会话
Ctrl+L                    # 清理终端屏幕
Ctrl+R                    # 搜索历史输入（由终端 Readline 提供）
Up / Down                 # 浏览历史输入
Left / Right              # 移动光标
Home / Ctrl+A             # 移动到输入行开头
End / Ctrl+E              # 移动到输入行末尾
Ctrl+U                    # 删除光标前的整段输入
Ctrl+K                    # 删除光标后的整段输入
Ctrl+W                    # 删除光标前的一个单词
Tab                       # 接受补全或完成路径（取决于终端和版本）
```

`Ctrl+C` 在不同状态下可能有不同作用：生成回复时用于中断生成，命令执行时用于停止命令，输入框中则通常用于取消当前输入。需要退出会话时，优先使用 `Ctrl+D` 或 `/exit`。

## 三、启动、恢复与退出

```text
codex                     # 启动新会话
codex --help              # 查看帮助
codex --version           # 查看版本
codex resume               # 选择并恢复历史会话
codex resume --last        # 恢复最近一次会话（若当前版本支持）

Ctrl+D                    # 退出会话
/exit                     # 退出 Codex
/quit                     # 退出 Codex（若当前版本支持）
Ctrl+C                    # 中断当前任务
```

不要把 `Ctrl+C` 当成唯一的退出方式。任务正在执行时，它首先会停止当前操作；在空输入状态下再次使用，才可能结束终端进程。

## 四、斜杠命令总览

斜杠命令用于控制会话，不是 Shell 命令。输入 `/` 后可以查看当前版本提供的补全列表。

```text
/help                     # 查看帮助和可用斜杠命令
/status                   # 查看当前会话、模型和权限状态
/model                    # 查看或切换模型
/approvals                # 查看或调整审批策略
/permissions              # 查看权限配置（若当前版本支持）
/clear                    # 清理当前对话显示或开始新上下文
/compact                  # 压缩较长的对话上下文
/exit                     # 退出当前会话
```

部分命令会随版本、启动参数和客户端形态变化。遇到命令无效时，不要直接猜测参数，先执行 `/help`。

## 五、常用会话操作

### 查看当前状态

```text
/status                   # 查看模型、工作目录、权限和上下文状态
```

### 清理和压缩上下文

```text
/clear                    # 清理当前会话内容
/compact                  # 压缩对话，保留任务相关上下文
```

当对话已经包含大量日志、重复尝试或不再相关的讨论时，先使用 `/compact`。如果要彻底切换到另一个任务，使用 `/clear` 或重新启动会话。

## 六、模型与推理设置

```text
/model                    # 打开模型选择或查看当前模型
```

命令行启动时也可以通过当前版本支持的参数指定模型。常见操作流程如下：

```text
/model
选择适合当前任务的模型
继续提交任务
```

模型选择建议：

```text
代码阅读和简单修改       # 使用响应速度较快的模型
跨文件重构和复杂调试     # 使用推理能力更强的模型
最终审查和风险检查       # 保留足够上下文，要求输出验证结果
```

不要只根据模型名称判断结果质量。对代码任务而言，是否读取了正确文件、是否运行了测试以及是否检查了差异同样重要。

## 七、审批与权限控制

Codex 可能在执行写文件、安装依赖、运行外部命令或访问网络前请求确认。

```text
允许一次                  # 只允许当前这次操作
允许本次会话              # 在当前会话中允许同类操作
拒绝                      # 拒绝当前操作
取消                      # 取消当前任务或返回输入框
```

查看或调整审批策略：

```text
/approvals                # 查看或修改审批设置
/permissions              # 查看权限配置（若当前版本支持）
```

安全的操作习惯：

```text
先查看命令再确认          # 确认命令的目录、参数和影响范围
先检查 git diff            # 确认修改是否符合预期
涉及删除、部署、推送时谨慎  # 这些操作通常具有不可逆或外部影响
```

不要为了减少确认而长期开启过宽的权限。对不熟悉的仓库，默认保留审批更适合排查问题。

## 八、Shell 命令执行中的控制

Codex 执行 Shell 命令时，仍然使用终端本身的控制键。

```text
Ctrl+C                    # 停止当前命令
Ctrl+Z                    # 挂起当前命令（由 Shell 提供）
Ctrl+L                    # 清理终端显示
Ctrl+D                    # 向当前程序发送 EOF，可能结束输入或退出程序
```

当 Codex 正在等待一个命令结束时，不要重复提交同一条请求。先判断命令是正常运行、等待输入，还是已经卡住，再选择中断或继续等待。

## 九、文件和目录引用

在请求中明确指出文件路径，可以减少 Codex 搜索范围。

```text
@README.md                # 引用文件（若当前客户端支持文件提及）
@src/                     # 引用目录（若当前客户端支持目录提及）
```

也可以直接在请求中写路径：

```text
阅读 source/_posts/example.md，检查 front matter 是否正确
只修改 src/components/Button.tsx
不要改动 package-lock.json
```

推荐写清楚三件事：

```text
目标文件                  # 允许读取或修改哪些文件
目标行为                  # 希望实现或修复什么
验证方式                  # 修改后运行什么命令
```

## 十、提示词编辑技巧

```text
Enter                     # 提交请求
Ctrl+U                    # 删除前半段输入
Ctrl+W                    # 删除前一个单词
Up / Down                 # 调出历史请求
```

较长的任务可以按下面的结构输入：

```text
背景：这个项目使用 Hexo 8。
目标：给文章代码块增加复制按钮。
范围：只修改 themes/hingle/source/js 和对应样式。
约束：保留现有主题风格，不引入新依赖。
验证：运行 npm run build，并检查生成的 HTML。
```

一次只描述一个可验证目标，通常比“全面优化整个项目”更容易得到稳定结果。

## 十一、让 Codex 先读再改

推荐使用明确的两阶段请求：

```text
先阅读相关文件，解释问题根因，不要修改文件
```

确认方案后再提交：

```text
按刚才的方案修改，保持改动最小，并运行针对性的验证命令
```

这适合以下场景：

```text
不熟悉的仓库              # 先了解项目结构和约定
影响范围不明确            # 先查找调用方和测试
涉及配置或部署            # 先确认命令和环境
修改公共 API              # 先检查引用和兼容性
```

## 十二、代码修改工作流

```text
1. 说明要解决的行为问题
2. 指定允许修改的目录或文件
3. 要求先阅读相关实现和测试
4. 让 Codex 进行最小修改
5. 查看 git diff
6. 运行针对性测试或构建
7. 再进行必要的补充修改
```

可以直接使用这样的请求：

```text
检查这个报错的根因。先读取相关实现和测试，不要修改文件。
确认后修复根因，只改动必要文件，并运行失败的测试。
最后总结修改文件、验证命令和仍存在的风险。
```

## 十三、查看差异与撤销修改

Codex 不应替代 Git 的审查流程。修改完成后，建议在终端执行：

```bash
git status                 # 查看修改文件
git diff                   # 查看未暂存差异
git diff --check           # 检查空白和补丁格式问题
git diff --stat            # 查看修改规模
git diff -- path/to/file   # 查看单个文件差异
```

在 Codex 中也可以请求：

```text
/diff                     # 查看当前修改差异（若当前版本支持）
/review                   # 对当前修改进行审查（若当前版本支持）
/undo                     # 撤销最近一次 Codex 修改（若当前版本支持）
```

`/undo` 的可用范围取决于客户端和版本。最可靠的恢复方式仍然是先确认 Git 工作区状态，再使用 Git 的撤销或恢复操作。

## 十四、代码审查工作流

```text
/review                   # 请求审查当前修改（若当前版本支持）
```

也可以使用自然语言提出审查要求：

```text
审查当前工作区修改，优先寻找：
1. 会导致错误行为的 Bug
2. 兼容性和安全风险
3. 缺失的边界条件
4. 缺失或不足的测试
不要直接修改文件，只输出按严重程度排序的问题。
```

审查结束后再提交修复请求：

```text
修复刚才确认的高优先级问题，只修改相关文件，并运行对应测试。
```

## 十五、上下文管理技巧

```text
/status                   # 查看上下文和会话状态
/compact                  # 压缩上下文
/clear                    # 清理会话
```

上下文快满时：

```text
保留：目标、约束、已确认根因、修改文件、测试结果
删除：重复日志、无关讨论、已经否定的方案
```

可以在压缩前要求 Codex 生成工作摘要：

```text
请总结当前任务的目标、已确认事实、已修改文件、测试结果和下一步计划，
保留可直接用于继续工作的具体路径和命令。
```

## 十六、MCP 与外部工具

如果当前 Codex 配置了 MCP，可以先查看可用工具，再决定是否调用。

```text
/mcp                     # 查看 MCP 服务器和工具（若当前版本支持）
/help                    # 查看 MCP 相关命令
```

使用外部工具前，应明确：

```text
工具将访问什么数据
是否会写入外部系统
是否包含敏感信息
失败后如何回滚
```

不要在提示词、日志或命令参数中直接粘贴密码、Token、私钥等敏感信息。

## 十七、Skills 与可复用工作流

部分 Codex 环境支持通过 Skills 扩展工作流。可以让 Codex 先列出当前可用能力：

```text
列出当前可用的 Skills，并说明各自适用场景
```

使用 Skill 时建议说明：

```text
使用指定 Skill 处理这个任务
只使用与当前问题相关的能力
完成后给出修改文件和验证结果
```

Skills 不是通用快捷键，实际名称和加载方式取决于当前客户端与项目配置。

## 十八、终端与编辑器配合

Codex CLI 适合负责分析、修改和验证；编辑器适合查看 diff、定位代码和处理交互式调试。

```text
Ctrl+`                   # 在 VS Code 中打开集成终端
Ctrl+P                   # 快速打开文件
Ctrl+Shift+F             # 搜索工作区
Ctrl+K, Ctrl+S           # 查看或修改 VS Code 快捷键
```

常用配合方式：

```text
Codex CLI                # 提出任务、读取代码、执行测试
VS Code                  # 查看差异、逐行检查、手动调试
Git                      # 保存历史、比较版本、回滚修改
```

如果在 VS Code 中使用 Codex 扩展，扩展自己的快捷键以“键盘快捷方式”中显示的绑定为准，不要把 CLI 的快捷键直接套用到扩展界面。

## 十九、常见任务模板

### 修复 Bug

```text
请复现并修复这个问题：<问题描述>
先阅读相关实现和测试，说明根因。
只修改必要文件，补充或更新最小测试。
完成后运行：<测试命令>
最后说明修改内容和验证结果。
```

### 新增功能

```text
请为 <模块> 增加 <功能>。
先检查现有接口、调用方和测试约定。
保持现有 API 风格，不引入新依赖。
实现后补充边界条件测试，并运行：<验证命令>
```

### 重构

```text
请重构 <文件或模块>，目标是 <目标>。
保持外部行为和公共 API 不变。
先列出影响范围，再分小步修改。
每一步都运行相关测试，并报告行为是否改变。
```

### 解释代码

```text
请阅读 <文件路径>，解释它的输入、输出、关键控制流和异常处理。
不要修改文件；如果发现潜在问题，请单独列出并说明证据。
```

## 二十、常见故障排查

### Codex 没有修改文件

```text
确认当前工作目录是否正确
确认请求中是否明确要求修改
检查是否停留在审批等待状态
查看 git status 和 Codex 输出
```

### Codex 修改范围过大

```text
Ctrl+C                    # 立即中断当前任务
查看 git diff              # 确认已经发生的修改
要求只修改指定文件
恢复无关修改后重新开始
```

### 命令执行失败

```text
检查错误信息中的实际命令
确认依赖、环境变量和当前目录
手动运行同一条命令确认是否可复现
把完整错误和复现命令提供给 Codex
```

### 上下文变得混乱

```text
/compact                  # 保留核心上下文
/clear                    # 任务已经切换时清理上下文
重新提供目标、范围和验证命令
```

## 二十一、Codex 使用原则

```text
先确认目录，再开始修改
先阅读相关代码，再提出方案
小步修改，每步验证
始终检查 git diff
让测试结果成为结论的一部分
涉及删除、部署和推送时人工确认
不要把凭据放入提示词或代码
```

Codex 可以执行大量重复工作，但最终的行为判断、差异审查和发布决策仍然应该由开发者确认。

## 二十三、推荐优先形成肌肉记忆

```text
Ctrl+C                    # 任务不符合预期时立即停止
Ctrl+D                    # 退出当前会话
/status                   # 确认工作目录、模型和权限
/help                     # 不确定命令时先查帮助
/compact                  # 对话变长时压缩上下文
/clear                    # 切换任务时清理上下文
```

相比记住所有命令，更重要的是形成下面的工作习惯：

```text
明确目标 -> 限定范围 -> 小步修改 -> 查看 diff -> 运行验证
```

```text

3. Ctrl+C 通常用于中断当前任务；退出会话优先使用 Ctrl+D 或 /exit。

4. Ctrl+L、Ctrl+R、Ctrl+U 等输入编辑行为可能由终端 Shell 提供，而不是 Codex 独有功能。

6. 不要在提示词、命令参数、日志或提交内容中暴露密码、Token 和私钥。
```
