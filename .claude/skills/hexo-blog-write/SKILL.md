# Hexo 博客文章写作 Skill

本 Skill 指导 Agent 按照你个人 Hexo 博客的既定格式和风格撰写新文章，自动匹配格式规范。

## 博客格式规范

### 1. 文件命名
- 文件名格式：`YYYY-MM-DD-文章标题.md`
- 保存位置：`source/_posts/` 目录下

### 2. Front Matter (YAML 头信息)
必须包含以下字段，顺序如下：
```yaml
---
title: 文章标题（不带日期前缀）
date: YYYY-MM-DD
categories:
  - 一级分类
  - 二级分类（可选）
tags:
  - 标签1
  - 标签2
  - 标签3
description: 文章简短描述（100字以内，概括文章内容）
---
```
- **title**: **不要带日期前缀**。日期只出现在文件名和 `date` 字段里，`title` 写纯标题（现有 147 篇文章中只有 2 篇例外，属于历史遗留，不要模仿）
- **date**: 发布日期，格式 `YYYY-MM-DD`，必须与文件名中的日期一致
- **categories**: 分类，从宏观到具体，通常 1-2 个
- **tags**: 标签，列出相关关键词，通常 2-4 个
- **description**: 可选但推荐，简要概括文章内容

**示例**：
```yaml
---
title: 2026-03-17-GitHub Pages 部署Hexo添加个性化域名的配置方法(腾讯云域名)
date: 2026-03-17
tags:
  - GitHub Pages
  - 网站
categories:
  - 工具配置
  - 进击的码农
description: 本文介绍如何为部署在 GitHub Pages 上的 Hexo 博客配置腾讯云个性化域名，包括购买域名、DNS 解析、CNAME 文件及 HTTPS 启用全流程。
---
```

### 3. 文章内容格式

#### 标题层级
- 一级标题：不需要，title 已经是标题
- 二级标题：`## 章节标题`，用于主要章节划分
- 三级标题：`### 小节标题`，用于子章节
- 四级标题：`#### 小点标题`，较少使用

#### 代码块
- 必须指定语言：\`\`\`bash, \`\`\`cpp, \`\`\`python, \`\`\`text 等
- 命令行操作使用 `bash`
- 代码使用对应语言
- 配置文件内容使用对应语言或 `text`

#### 链接与图片
- 外链：`[链接文字](URL)` 格式
- 图片：`![图片说明](图片URL)`，使用腾讯云 COS 图床，URL 格式：`https://tk-pichost-1325224430.cos.ap-chengdu.myqcloud.com/blog/[hash].png`

#### 分隔线
- 不同大步骤之间用 `---` 加分隔线，使文章结构更清晰

#### 引用
- 提示说明使用 `> 注意：……`

#### 多语言代码块（重要）
算法竞赛类文章需要同时给出 C++、Python、Java、Go、Rust 五种语言的实现，逻辑完全一致。

博客启用了代码块 tab 切换，会把**连续的**多个围栏代码块合并成一组可切换的 tab
（标签为语言名，默认停在第一个）。因此多语言代码块之间**绝对不能插入 `### 语言名` 之类的标题**，
否则相邻性被打断，tab 不会生成。

正确写法（代码块之间只留一个空行）：

````markdown
```cpp
cout << "Hello";
```

```python
print("Hello")
```
````

错误写法：

````markdown
### C++
```cpp
// ...
```

### Python
```python
# ...
```
````

其他约束：
- 章节标题只写 `## 代码实现`，不要写成 `## 代码实现（C++）`
- 引言句要提示读者可以切换标签
- 「思路讲解」部分的零散代码片段不受此约束，可以照常用 `###` 组织
- 五种语言必须逻辑等价、惯用写法到位（Python 类型注解、Go 用 bufio、Rust 用 String、Java 用 StringBuilder、C++ 记得 `cin.tie(nullptr)`）

#### 参考资料
- 文章末尾放参考资料：
```
### 参考
- [参考文章标题](URL)
```

### 4. 写作风格

- **开门见山**：开头直接说明文章要解决什么问题
- **步骤清晰**：操作指南按步骤编号，每一步讲清楚做什么
- **代码完整**：完整给出可复制的命令/代码，不要省略关键部分
- **包含排错**：常见问题放在文章末尾"常见问题排查"部分
- **结尾友好**：教程类文章结尾可以说"好啦，感谢大家的观看"等
- **中文标点**：使用标准中文标点符号

### 5. 常见文章结构（教程/概念类）

标准结构顺序（参考资料**必须放在文章末尾**）：

```
---
Front Matter
---

## 概述（引言）
说明本文解决什么问题，概述核心内容

---

## 第一章 主题一
内容...

### 小节 1.1
内容...

---

## 第二章 主题二
内容...

---

## ...（更多章节）

---

## 总结
总结核心要点

---

（可选）好啦，感谢大家的观看，如果有疑问欢迎留言交流～

### 参考
- [参考文章标题](URL)
- [参考文章标题](URL)
```

**重要规范**：
- `### 参考` 部分必须放在文章**最末尾**，不要放在开头
- Front Matter 之后直接进入正文，不要把参考资料放在开头

## 使用时机

- 用户需要撰写新的 Hexo 博客文章
- 用户要求按照博客现有格式生成文章
- 用户需要新建博客文章文件
