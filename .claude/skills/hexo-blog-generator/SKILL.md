# Hexo 博客文章生成器

本 Skill 根据个人博客的格式规范，自动生成符合要求的新文章。封装了博客现有的命名规则、Frontmatter 格式、文章结构模板和写作风格，一键生成可直接发布的文章。

## 使用时机

- 需要写一篇新博客文章
- 需要按照固定格式生成 LeetCode 刷题笔记
- 需要写论文阅读笔记
- 需要记录环境配置过程
- 需要写技术教程或问题解决记录
- 需要记录生活/硬件维护经历

## Step 1：识别文章类型

根据用户表述选择对应模板：

| 文章类型 | 模板文件 | 适用场景 |
|---------|---------|---------|
| 算法笔记 / 刷题 | `templates/algorithm-note.md` | LeetCode 刷题、算法题解、竞赛笔记 |
| 技术教程 / 问题解决 | `templates/tech-tutorial.md` | 技术教程、问题排查经验分享 |
| 论文阅读 | `templates/paper-reading.md` | 论文阅读笔记、精读总结 |
| 环境配置 | `templates/env-setup.md` | 软件安装、环境搭建配置记录 |
| 生活记录 | `templates/life-journal.md` | 生活随笔、硬件维护、个人记录 |

如果用户未明确类型，根据标题内容推测，或追问用户确认。

## Step 2：收集必要信息

按顺序收集以下信息，缺失则追问：

1. **文章标题** - 用户提供标题
2. **文章核心内容/要点** - 用户简要说明要写什么
3. **发布日期** - 默认为今天（`{{date}}`），用户可修改
4. **分类（categories）** - 根据类型自动建议，显示给用户确认可修改
   - 算法笔记：`["算法蒟蒻的成长记录", "LeetCode"]`
   - 论文阅读：`["Give me some papers"]`
   - 环境配置：`["环境配置"]`
   - 生活记录：`["生活记录"]`
5. **标签（tags）** - 根据标题和类型自动建议 3-5 个，用户可增删
6. **输出路径** - 默认为 `/d/code/my_hexo_blog/source/_posts/`

## Step 3：生成文章

1. 根据类型读取对应模板
2. 自动生成文件名：`YYYY-MM-DD-标题slug.md`
3. 填充 Frontmatter，自动填入日期、分类、标签
4. 根据用户提供的要点展开成文，保持现有博客的写作风格
5. 输出完整 Markdown 内容，并写入目标文件

## 格式规范（严格遵守）

### 算法笔记的多语言代码（重要）

算法竞赛类文章（`templates/algorithm-note.md`）的「代码实现」章节**必须给出 5 种语言的实现**：
C++、Python、Java、Go、Rust。五者逻辑完全一致，只换语法。

**排版铁律：多语言代码块之间绝对不能插入任何标题。**

博客启用了 `scripts/code-tabs.js`，它会把**连续的**多个围栏代码块合并成一组可切换的 tab
（标签为语言名，默认停在第一个）。只要中间夹了一个 `### C++` 之类的标题，
相邻性就被打断，tab 不会生成，文章会退化成五段平铺的长代码。

正确写法——代码块之间只留一个空行：

````markdown
```cpp
cout << "Hello";
```

```python
print("Hello")
```
````

错误写法（`###` 标题会打断合并）：

````markdown
### C++
```cpp
// ...
```

### Python
```python
# ...
```
````

**其他约束：**

- 章节标题只写「## 代码实现」，不要写成「## 代码实现（C++）」——标题里带单一语言名会误导读者以为文章只有一种语言
- 引言句要明确提示可以切换标签，例如「以下给出 C++、Python、Java、Go、Rust 五种语言的实现，逻辑完全一致。切换上方的标签即可对比。」
- **「思路讲解」部分的代码片段不受此约束**。讲思路时穿插的零散片段（如单独演示 `first` 标志的用法）可以照常用 `###` 小标题组织，因为它们本来就不是一组对比实现
- 只有当题目确实需要多种语言对比时（如《多项式输出》《最小差值平方和》）才用这个排版；纯 LeetCode 刷题笔记若只写一种语言，也不要强行凑齐 5 种

### 多语言代码的内容要求

- 五种语言必须**逻辑等价**，不要出现「C++ 写了完整版、Python 只写了核心部分」这种参差
- 各语言的惯用写法要到位：Python 用类型注解和 `def main()`，Go 用 `bufio` 读入，
  Rust 用 `String` 累加，Java 用 `StringBuilder`，C++ 记得 `ios::sync_with_stdio(false)` 与 `cin.tie(nullptr)`
- 注释保持简洁，说明关键步骤即可，不要逐行翻译

### 文件名
- 格式：`YYYY-MM-DD-文章标题.md`
- 示例：`2026-01-19-LeetCode刷题笔记-1292-元素和小于等于阈值的正方形的最大边长.md`
- 算法笔记的常用命名：`YYYY-MM-DD-LeetCode刷题笔记-题号-题名.md`

### Frontmatter
```yaml
---
title: 文章标题
categories:
  - 分类名
date: YYYY-MM-DD
tags:
  - 标签1
  - 标签2
---
```
- **title 不带日期前缀**，只有文件名和 `date` 带日期。现有 147 篇文章中仅 2 篇 title 带日期，属历史遗留，不要模仿

### 写作风格
- 层级清晰：`#` 一级标题，`##` 二级标题，`###` 三级标题，不超过四级
- 代码块：必须指定语言，缩进正确
- 图片：`![filename.png](https://tk-pichost-1325224430.cos.ap-chengdu.myqcloud.com/blog/filename.png)`
- 大段内容用 `---` 水平分隔线分隔
- 中文与英文/数字之间加空格，使用全角中文标点
- 使用 `**粗体**` 强调重点，使用 `行内代码` 标记命令和变量
- 每篇文章结尾必须有总结段落
- 语气亲切自然，可适度使用幽默表达

### 分类标签约定
- 主分类不超过 2 个
- 标签通常 2-5 个，与文章内容强相关
- 常用分类：`环境配置`、`算法蒟蒻的成长记录`、`Give me some papers`、`生活记录`、`程序开发`
