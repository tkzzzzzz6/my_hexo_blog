# 小任务的提交与验收

1. 先在 Issue 写清问题、改动范围和可检查的完成标准。
2. 使用独立任务分支/worktree，保留其他目录的修改和暂存状态。
3. PR 正文通过 `Fixes #编号` 关联任务。
4. 运行 `npm run lint:agent`、`npm run test:agent`、`npm run check:build`。
5. 低风险或事先授权的任务由默认分支控制器判定；标签不是授权。
6. 新提交需要重新检查；冲突在任务分支解决后再次验证。
7. 全局模板、依赖、工作流和部署配置交由维护者验收。

具体边界、人工验收和回退步骤见 [完整流程](../agent-workflow.md)。

自动合并与自动发布是两个独立开关。源码与线上内容尚未对齐时，
保持自动发布关闭；文档 PR 的合并不意味着网站已经重新部署。
