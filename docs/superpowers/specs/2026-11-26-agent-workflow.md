# Agent 分级合并设计

> 历史设计：维护者现已改为 Feature 内集成、阶段结束一个 PR，Agent 只交付 PR，维护者自行合并。此页的自动合并和环境验收不再适用；当前规则见 [交付流程](../../agent-workflow.md)。

对应 Issue #34。维护者已确认方向：Agent 自主处理低风险实现、冲突与合并；全局设计、高风险配置和重要功能由维护者验收。

## 架构

- `pull_request` 执行无部署凭据的 lint、Node 行为测试、干净 Hexo 构建和产物检查。
- `pull_request_target` / `workflow_run` 控制器只检出默认分支的策略与脚本，只通过 API 读取 PR 元数据和文件清单，绝不执行 PR 代码。
- 默认低风险仅限 README 和 `docs/guides/` Markdown。一般功能通过默认分支中事先审查的单 Issue 路径授权放行；策略、依赖、部署、权限、网址和删除/重命名始终人工验收。
- 人工验收使用受保护的 `maintainer-approval` Environment，绑定当前 PR head SHA；合并后重新验证线上页面。
- 自动合并默认关闭，基础设施 PR 由维护者审查。合并后使用受审查的设置脚本启用 Actions、环境审批和主分支保护，再开启仓库变量。

## 约束

不改站点功能与既有未提交文件。不接触凭据。不自合并本 PR。共享管理员身份只能提供流程约束；强权限边界需要受限 Agent 身份，文档明确说明。

## 验收

拒绝策略自改、标签伪造、路径穿越、删除/重命名、过大 diff、过期提交、外部 fork、失败/跳过的必需检查。lint/test/build 结果可复查；CI 检查内容而不只信任 Hexo 退出码。全局 PR 不能被自动合并。
